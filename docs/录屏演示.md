# 课堂录屏操作参考

按约2分40秒设计。可依自己的语速调整，画面切换应给听众留出阅读时间。此脚本适合展示软件原型，无法替代包含实地影像、访谈和调研发现的完整实践微纪录片。

## 开始前

1. 双击 `启动展示.cmd`，最大化浏览器，确认进入序章。约10秒后轴线点亮完毕，也可随时点击“跳过开场”。页面底部“重播开场”可重新开始。
2. 当前没有真实调研材料，展示“青年尝试”中的路线、方法和待开展测试任务即可。后续取得材料时，可按 `Shift+M` 进入管理模式录入，录屏前再返回展厅。
3. 按 F11 或点击右上角全屏，调整系统分辨率和浏览器缩放，确保文字可读。可按 R 弱化页眉与页脚。录屏用电脑已有的软件完成。
4. 建议手动切换节点，避免自动导览与讲解节奏不一致。需要连续画面时再开启自动导览。

## 0:00—0:25 / 建立主题

画面：从序章点亮动画开始，点击“进入中轴”进入第一章，再点击故宫、正阳门。

讲解参考：

> 这是我们制作的“智护中轴·数启文脉”数字导览原型。北京中轴线纵贯老城南北，全长7.8公里，包含15个遗产构成要素。我们希望研究公众理解遗产时遇到的问题，先制作可以操作的小工具，再通过真实体验来检验和改进。

## 0:25—0:50 / 读懂中轴

画面：点击景山、先农坛，展示右侧知识卡。切换一次历史图层，再回到全景。

讲解参考：

> 在地图中点击节点，可以看到“是什么、现场看什么、数字技术能做什么”。例如在景山，我们关注整体空间和南北视线。在先农坛，我们关注传统建筑知识如何通过实物、模型和展陈被公众理解。历史图层用于强调不同时期的叙事重点，地图和建筑都是讲解示意。

## 0:50—1:25 / 科技守护

画面：点击“下一章”进入科技守护。拖动三维城楼观察侧面，点击“自动环绕”短暂停留后暂停；将结构展开滑块从0拖到100，再点击“复位”。如果时间充足，可补充线框观察或模拟监测情景。

讲解参考：

> 这座城楼是依据公开照片与建筑说明制作的风格化三维样板，可以换角度观察，也能分开展示屋檐和柱廊的层次。它不是测绘复原。另一侧的预设曲线说明连续记录和变化提示的思路，没有连接真实设备。实际文物保护仍需要专业采集、资料建档、连续观察和人工研判。

## 1:25—1:50 / 科技讲活

画面：进入科技讲活，展示正阳门示意及数字展示、交互理解、数字传播的说明。

讲解参考：

> 文化遗产的保护还需要公众理解。我们以正阳门为例，先通过图形建立空间印象，再用交互和简明知识卡解释建筑。数字传播可以把这些知识组织成适合手机阅读的内容。原型能否帮助理解，还需要后续测试。

## 1:50—2:15 / 青年尝试

画面：进入青年尝试，展示两次路线、FIND / BUILD / TEST 的阶段说明和体验任务，不进入管理模式。

> 当前我们已经制作了可操作原型，现场需求观察和真实用户测试仍待开展。我们计划让体验者找到正阳门、说出观察重点，再展开建筑结构，记录哪些步骤难以理解，并据此改进。

## 2:15—2:40 / 回到课程

画面：进入尾声，展示课程知识点与保护、传播、青年实践的对应关系。

> 这个原型对应课程中深入实施创新驱动发展战略的知识点。我们的尝试从具体需要出发，用软件工程所学把知识重新组织，再邀请真实体验者完成任务并提出意见。原型是否有效，仍要看真实操作记录与反馈。通过这样的实践，我们理解科技创新怎样进入文化保护与传播的具体场景。

## 可选的体验任务

给体验者一句任务：“找到正阳门，说出一个现场观察重点，再打开科技守护章节，把建筑结构展开。”

记录其是否独立完成、在哪一步停顿、用了多长时间、提出什么具体问题。反馈表只记录理解感受，不能单凭均分证明原型有效。保留真实测试记录，比较修改前后的具体问题。
